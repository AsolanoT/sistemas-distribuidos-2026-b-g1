Decisions made

01

No version in the URL

Keep /api/customers, not /api/v1/customers — every existing document already uses this format; versioning now would break traceability with what has already been approved.

02

The Gateway validates the JWT only once

The 4 domain services no longer validate the token — they trust the X-User-Id / X-User-Roles headers forwarded by the Gateway (ADR-003 §2).

03

Sale registration is now internal

POST /api/sales is no longer called directly by the frontend — it is called by synkro-workflow as step 3 of the Saga, after validating the customer and reserving stock.

04

Stock reservation and release share the same mechanism

Inventory (manual adjustment) and the Saga (reservation/compensation) use the same 2 operations — the business rule (stock can never be negative) is identical regardless of who calls.

Blockers and gaps found

⚠

synkro-workflow / synkro-worker stack not defined

It does not block the contracts already written (OpenAPI describes the interface, not the implementation), but it does block starting development of those 2 services.

⚠

There is no way to search for a customer by document

The data model assumes it ("point of sale lookup"), but ADR-001 did not define that endpoint. Decision pending — resolved in ADR-004.

⚠

There is no endpoint to create product categories

It is assumed that the categories already exist in the database. Same pending solution — ADR-004.
